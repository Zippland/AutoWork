# AutoWork

本地个人 AI 工作台，当前应用名为 TaskPilot。使用已经安装的 AI CLI 整理背景、查看工作、接收修改意见，并按你的节奏推进事项。

工作推进与背景整理各自保存独立会话，互读已发布成果；界面负责交互、调度、审批和验收，模型负责理解与执行。

需要 Node.js 22+、pnpm 10，以及至少一个已安装并登录的本地 AI CLI（Codex、Claude Code 或 Trae CLI）。

```sh
git clone https://github.com/Zippland/AutoWork.git
cd AutoWork
pnpm install --frozen-lockfile
pnpm dev
# 正式运行
pnpm build
pnpm start
```

未安装 pnpm 时，可在已安装 Node.js 的环境运行 `npm install --global pnpm@10.28.2`。本项目目前以 macOS 本地运行为验证环境。

默认地址 `http://127.0.0.1:4317/`，数据目录 `~/.TaskPilot/`。支持 `TASKPILOT_PORT` 和 `TASKPILOT_DATA_DIR`；服务仅监听本机。

## 第一次使用

1. 在仓库目录执行上面的安装、启动命令，打开 http://127.0.0.1:4317/ 。首次启动自动创建空白数据目录、AGENTS.md 和 skill，不导入旧工作台资料。
2. 在引导页选择已登录的本地 AI，等待连接成功。此时只展示必要设置，不显示看板或启动日常巡检。
3. 点击“开始调研背景”。AI 通过已有工具了解近期工作，把背景摘要保存到文件。期间可以查看进度、通过背景对话补充线索或单独停止；中断后可继续调研。
4. 摘要准备好后，先查看 AI 对你的理解；有偏差直接对话调整，再点击“进入工作台”。之后可以交办、审核和验收，在“设置”调整自动推进与巡检时间。

引导进度由连接状态、背景文件和宿主保存的进入记录恢复，刷新页面不会重头开始。背景未产出时不能进入工作台；用户进入前不执行日常巡检或自动推进。关闭终端或按 Ctrl+C 会停止服务与本地巡检，再次启动会继续读取已保存的资料。

## 使用

- 右上角“推进”：把已保存的审阅意见一次提交，启动一轮全局调研与推进，优先处理这一批。按钮旁显示距下次自动推进的倒计时，按设置的工作日和时段计算；暂停或未开启定时时显示对应状态。运行或排队时按钮禁用；卡片仍可保存意见，留给下一批。
- 工作看板 / 列表：查看应做事项与可主动推进的事项，按项目和来源筛选。显示方式是所有事项页面共用的偏好，保存在当前浏览器，切换页面、刷新或重新打开后沿用。
- 待我审核：看具体方案和需要决定的内容。批准绑定当前文件版本，不扩展为其他操作的授权。
- 事项详情：在卡片右侧保存批注、批准方案，继续审阅其他卡片；点顶部“推进”后统一处理。“活动”保留批注、审核和回报；未保存草稿按卡片保存在浏览器，已保存意见持久化到本机。验收与暂停立即生效。
- 保存修改意见或批准方案后，事项移入“待推进”，不再催用户审核旧方案。手动或定时推进接收这一批后，自动进入“跟进中”；排队与运行由宿主状态显示。发布结果后，再按新结果决定是否需要用户审核或验收；撤回未提交意见恢复原状态。这个交互状态由宿主展示，不改写模型的资料文件。
- 资料与成果：点击本地附件，在工作台内直接阅读 Markdown 正文、表格和引用；关闭资料回到原卡片，批注草稿保留。资料中的本地引用可继续阅读并返回上一份，其他文本显示原文，也可以下载原文件。
- 跟进中：正在执行，或等待他人和外部结果。AI 通过巡检继续核实，不为等待而反复空跑。
- 待我验收：AI 已交付，用户验收后才进入归档。
- 需要关注：自由 Markdown 摘要，不自动变成待办。
- 我的背景：只读展示 `background/SUMMARY.md`，页面内的背景助手负责对话修正；“立即总结”启动调研整理。工作聊天只在右侧工作助手中进行。
- 设置：选择 Codex / Claude Code / Trae CLI，控制自动推进，修改巡检频率、日期和时间。默认中国法定工作日 10:00–22:00，当天巡检每 30 分钟，背景每 12 小时。手动交办随时执行。

## 文件

```text
~/.TaskPilot/
  AGENTS.md                         共同工作约定，可依据已确认反馈维护
  CLAUDE.md                         引用 AGENTS.md
  .agents/skills/taskpilot-files/   目录协议
    prompts/work.md                每轮读取的推进计划，模型可维护
    prompts/daily.md               日常调研与推进计划
    prompts/background.md          背景调研计划
  workspace/
    SYSTEM.json                     宿主保存的交互、队列、运行与授权
    background/SUMMARY.md           展示给用户的近期背景
    assistant/ATTENTION.md           可选的关注摘要
    tasks/<id>/SUMMARY.md            事项摘要及少量交互元数据
    tasks/<id>/...                   模型自由组织细节、证据与成果
  recovery/<run-id>/                 中断时保留的未发布草稿
```

SUMMARY.md 使用 JSON 文件头：title、status、request；category 区分应做和主动推进，可选 project 用于导航。正文和资料结构完全由模型决定。`waiting` 表示等待外部结果；`done` 表示待验收，`archived` 只能由用户验收产生。

## 触发与执行

系统只有工作与背景两个持久逻辑会话：固定 ID、各自对话和运行记录保存于 SYSTEM.json。CLI 按轮次启动，从文件与历史接续；切换 harness 不改变会话记录。两者可读取对方已发布成果，分别写入工作目录（assistant/、tasks/）和背景目录（background/）。每轮工作先读最新背景。启动只来自定时、手动推进/总结与各自对话；卡片保存、文件变化、todo 状态不触发执行。定时工作推进会一次接收当时已保存的审阅意见，使用与手动推进相同的版本校验与批次边界；背景不受影响。运行期间的新意见不会打断当前轮或被提前消费。失败保留记录与草稿。定时由本地服务按工作日和时间窗口判断，服务休眠或关闭时不执行，不补跑积压轮次。

每轮工作推进重新读取已安装的 work.md 和 daily.md，背景通道读取 background.md。先通览工作台，优先处理本轮反馈，再按需增量调研和推进其他相关工作，复用近期证据。这些 prompt 是模型可维护的计划，改动下一轮生效，不需要重启；卡片的具体计划自由保存在事项目录。程序只注入当前交互、所选事项和触发时间等运行上下文。

每一轮从数据根目录启动本地 CLI，沿用它原有的登录、模型、工具、插件、MCP 和权限配置。新增文件工具只是方便管理工作台资料，原生工具仍可使用。当前支持 Codex、Claude Code、Trae CLI 的原生非交互协议；Trae 按本机版本区分 Coco 的 print 和 2.x 的 exec。通过设置切换，工作资料不随执行器切换迁移或丢失。

TaskPilot 只保存使用哪个执行器，不维护模型列表或 effort 选项，也不向 CLI 传递模型、推理强度覆盖参数。需要调整时，在对应 harness 的原生配置中修改，下一轮沿用。Claude 子进程读取已保存的原生环境配置；如果配置使用 `apiKeyHelper`，清除启动器遗留且未在配置中明确指定的认证变量，避免旧 token 和新接口混用。用户的全局配置与凭据不会被改写。

模型在临时副本中整理工作台文件。结束后只验证格式、路径、版本冲突和用户验收约束，随后一次发布文件和回复。外部动作不在文件事务里；要核实结果，不能因本地失败而盲目重发。CLI 失败不会自动重试，调研失败暂停自动巡检，手动重试成功后恢复。

查看本应用自己的页面只读；不代替用户点击批准、验收、暂停或发送聊天。飞书等外部工具按用户授权正常操作。详细设计见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 开发

独立 React + TypeScript + Node 项目，没有上游工作管理系统的组件、样式或运行时依赖。`src/` 是界面，`core/` 是纯协议和时间窗口，`server/` 是本地文件与执行器。

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm build
pnpm validate -- ~/.TaskPilot/workspace
```

GitHub Actions 会在推送和 Pull Request 时执行以上四项检查。开发约定、隔离运行和目录说明见 [开发指南](docs/DEVELOPMENT.md)，当前验证范围见 [验证记录](docs/VALIDATION.md)。

默认测试仅使用临时资料和受控 CLI；真实模型烟测需用户明确授权并设置 `TASKPILOT_RUN_REAL_AGENT_SMOKE=1`。真实账号与事项不用于点击审批、外发或归档的界面测试。
