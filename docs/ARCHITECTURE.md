# 架构

AutoWork 是独立的本地应用，当前界面和文件协议使用 TaskPilot 名称。React 界面与 Node.js 服务一起运行，服务仅监听 `127.0.0.1`，无需部署数据库或远端控制台。

## 两个会话

```text
手动推进 / 定时 / 工作对话 → 工作会话 → assistant/、tasks/
立即总结 / 定时 / 背景对话 → 背景会话 → background/
```

两个持久逻辑会话有固定 ID、独立的对话与运行记录，保存在 `workspace/SYSTEM.json`。CLI 按轮次启动，从已保存的历史和文件接续，而非依赖某个 harness 的原生会话永久驻留。切换执行器不改变工作资料或这两份历史。

两条通道可并行，各通道内部串行。两者互读已发布成果，各自只发布负责目录中的文件。每轮工作先读取最新的 `background/SUMMARY.md`；背景会话可参考工作资料。卡片是工作会话的持久资料，不创建额外 agent。

背景会话负责从用户的修改意见中理解其工作模型，与近期工作背景一起自由研究、整理到 `background/`，通过 `SUMMARY.md` 提供入口。宿主在背景轮次的临时副本中提供只读 `WORK_HISTORY.jsonl`，由 `INTERACTIONS.md.workHistoryFile` 引用：含本轮开始时全部工作对话和已提交意见，保留原始角色、时间、消息 ID 和事项关联，不受近期对话 100 条上限影响。未提交和已撤回的意见不进入快照；它是研究材料，不会提交意见或触发工作，也不是背景 agent 的执行指令。模型自行增量阅读和保留适用范围，宿主不做语义分类；原始记录仍保存在 `SYSTEM.json`，工作会话继续只需读取最新背景。

## 人与 AI 如何交接

1. 用户在卡片内保存意见、批准方案或要求继续推进，宿主保存为待推进记录，卡片进入“待推进”。保存不会启动或中断 AI。
2. 用户点击顶部“推进”，或到达设置中的定时时间，宿主原子接收当时已保存的这一批。批准记录绑定具体文件版本，过期版本不能继续使用。
3. 卡片自动进入“跟进中”，区分排队和运行。模型通览工作台，将本批意见纳入全局判断，所有可推进事项统一考虑，不因有批注而自动优先；保存意见和点击推进本身不构成新的外部动作授权。
4. 运行期间新保存的意见留给下一批。本轮发布新结果后，按新的请求显示待审核、等待结果或待验收；还有未提交意见的卡片仍留在待推进。
5. 用户验收后才能归档。模型不能伪造批准、验收或归档记录。

工作聊天在右侧助手中，背景聊天位于“我的背景”页内。两者直接对话各自启动对应会话。文件变化与卡片 `todo` 状态不构成自动触发。

## 调度

日期、时段和频率由宿主判断，默认中国法定工作日 10:00–22:00，时区为 Asia/Shanghai。当天工作每 30 分钟、背景每 12 小时复查，可在设置中修改。手动操作不受工作时段限制。

顶部倒计时使用服务返回的下一次自动推进时间，前端仅更新显示，不自行触发任务。正在运行时等待本轮结束后重新安排；暂停、未连接或定时关闭时不承诺自动执行。

服务每 5 秒检查一次调度。电脑休眠或服务关闭时不执行，不补跑积压的所有轮次。工作日历来自 `chinese-days`；超出依赖覆盖的年份时停止自动判断并提示更新。自动运行每日最多 96 次（UTC），手动请求不占该上限。

首次引导完成前，不执行日常工作巡检。用户先连接 AI、调研并查看背景，确认进入后才展示工作台并安排未来的定时任务。

## 文件与发布

持久数据默认位于 `~/.TaskPilot/`，可用 `TASKPILOT_DATA_DIR` 更改。每个事项用 `SUMMARY.md` 保存少量 JSON 文件头与自由 Markdown 正文，细节、证据和成果通过相对链接引用。宿主负责协议验证，不规定知识分类或研究步骤。

模型在本轮临时副本中工作。结束后校验文件格式、路径、大小、版本冲突、目录归属及验收约束，再一次发布本通道负责的目录。另一条通道并行更新的资料不会被旧副本覆盖。

`SYSTEM.json` 保存宿主交互记录；`INTERACTIONS.md` 是每轮只读的上下文快照，包含本批意见、关联事项及实际授权，关联关系不表示优先级。失败保存未发布草稿到 `recovery/`，相应自动调研暂停，手动重试成功后恢复。外部操作不在文件事务中，失败后须核实真实结果，不能盲目重发。

Markdown 附件在工作台内阅读，支持表格与相对引用；其他文本显示原文，二进制文件提供下载。本地文件访问限制在数据目录内，页面内容不执行任意 HTML 或脚本。

## 执行器与提示词

支持 Codex、Claude Code 和 Trae CLI 的本地非交互协议。执行器沿用用户自己的登录、模型、effort、工具、skill、MCP 和权限配置，应用只选择执行器，不覆盖模型配置。Trae 根据探测到的 CLI 能力选择对应调用协议。

全局运行状态统一显示在顶部和工作助手中，卡片只显示自身状态、意见与活动，不重复全局进度。运行进度来自进程启动和 CLI 实际事件。只在结束时返回结果的执行器会明确显示该限制；界面计时不伪造运行进展。默认测试全部使用受控 CLI，真实账号验证需要单独授权。

初始化在数据根目录安装 `AGENTS.md`、引用它的 `CLAUDE.md` 和 `.agents/skills/taskpilot-files/`。工作通道每轮读 `prompts/work.md` 与 `daily.md`，背景通道读 `background.md`。模型可以维护这些计划，下轮加载最新内容。初始化只补缺失文件，不覆盖用户或模型已维护的规则。

飞书只是工具路径之一：lark-cli 用于批量检索和读取，浏览器用于网页核实、补充上下文和发送消息。执行前读取对应工具的 skill，入口和账号来自用户现有环境，不绑定特定组织。
